# ADR-0011: CI/CD con GitHub Actions

- **Estado:** aceptada
- **Fecha:** 2026-11-07

## Contexto

Cada cambio tiene que validarse automáticamente y acabar desplegado sin pasos manuales. El repositorio es privado y está en GitHub. La preproducción está en el homelab, que no es accesible desde los runners alojados por GitHub ([ADR-0012](0012-entornos.md)).

## Decisión

- **CI**, en cada PR y en cada push. Usa los runners de GitHub, con Node y pnpm tomados de `package.json` ([ADR-0009](0009-toolchain-pnpm-node.md)):
  1. Instalación con `--frozen-lockfile`.
  2. `format:check`, `lint` y chequeo de tipos.
  3. Tests: incluyen la validación del catálogo, la estabilidad de IDs y el determinismo del builder.
  4. Generar `catalog.json` y fallar si difiere del versionado en el repositorio.
  5. Build de `apps/web`.
- **CD a preproducción**: cada push a `main` con la CI en verde despliega automáticamente. Lo ejecuta un _self-hosted runner_ dentro del homelab, que solo hace conexiones salientes. Se despliega el mismo artefacto que construyó la CI, sin volver a construirlo.
- **CD a producción**: se añadirá cuando se decida dónde va producción, como una promoción manual del mismo artefacto. El mecanismo concreto se elegirá según lo que permita el plan gratuito de GitHub para repositorios privados.
- **Seguridad de la cadena de suministro**: las acciones de terceros se fijan por SHA, y Dependabot las mantiene actualizadas.
- **Futuro**: cuando haya backend, las migraciones de base de datos serán un paso previo al despliegue del backend.

## Alternativas descartadas

- **SSH desde los runners de GitHub hasta el homelab**: obliga a exponer SSH y a gestionar credenciales hacia dentro de la red. Hay más superficie de ataque.
- **Despliegue por sondeo** (el homelab vigila si hay artefactos nuevos): se pierde el control del orden y no encaja con las migraciones futuras.
- **Todo en un self-hosted runner**: la CI depende de que el homelab esté encendido.

## Consecuencias

- La CI consume la cuota limitada de minutos gratuitos que GitHub da a los repositorios privados. Si se queda corta, los trabajos pueden pasar al runner del homelab.
- El runner del homelab necesita mantenimiento: actualizaciones y aislamiento.
- Un self-hosted runner no se puede usar si el repositorio pasa a ser público.
